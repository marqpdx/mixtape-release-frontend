# Shuttle weave-to-packet Strategy

Interpret the original telling and immutable corrections before preparing the
publication packet. Return provisional Sightings, not publishable rows.

Keep source preparation, mention extraction, story attribution, entity/Idea
resolution, intended-connection interpretation, and clarification as distinct
units. One bounded request may return several units; route units independently
by capability and privacy policy as fidelity permits.

The person owns meaning. State the proposed connection and quote the intent
evidence. Preserve firsthand story text verbatim. Return few useful questions;
keep uncertainty rather than silently filling gaps from research or fixtures.

A correction adds a source; it does not rewrite the original telling. Drop stale
results. Core owns source records, resolution and later packet assembly;
Switchboard gates/routes; Inkwell executes stateless local work; approved cloud
work uses the person's Core-managed runtime. No publication in interpretation.

Worked example: `spoken_choirs.findings.json` alongside the shared API contract
and Core validation package. It contains only one stated Idea and one firsthand
story, unlike the polished SH-7a fixture.
